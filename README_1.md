# 세미나 기획 데스크

NE능률 디지털서비스본부 디지털마케팅팀 · 세미나 요청 접수 및 진행현황 조회

---

## 1. 구성 파일

| 파일 | 위치 | 역할 |
|---|---|---|
| `index.html` | GitHub 저장소 최상단 | 화면 전체 (단일 파일, 외부 라이브러리 없음) |
| `Code.gs` | 구글시트 Apps Script | 구글시트 저장·조회 API |
| `README.md` | GitHub 저장소 최상단 | 본 문서 |

## 2. 배포 순서

### 2-1. 구글 Apps Script 먼저

1. 구글시트 열기 → 상단 메뉴 **확장 프로그램 → Apps Script**
2. `Code.gs` 내용 전체를 붙여넣고 저장(Ctrl+S)
3. **배포 → 배포 관리 → 연필(수정) → 버전 "새 버전" → 배포**
   (처음이라면 **새 배포 → 웹 앱 → 실행 계정 "나" → 액세스 "모든 사용자" → 배포**)
4. 나오는 **웹 앱 URL**을 복사

> **액세스 권한은 반드시 "모든 사용자"여야 합니다.**
> "나만" 또는 "Google 계정이 있는 모든 사용자"로 두면 웹앱 URL이 구글 로그인 페이지로 넘어가면서
> Vercel 화면에서 목록이 조회되지 않습니다.
>
> **확인 방법**: 웹앱 URL을 시크릿 창(로그인 안 된 상태)에서 열어보세요.
> - `{"ok":true,...}` 형태의 JSON이 보이면 정상
> - 구글 로그인 화면이 뜨면 권한 설정이 잘못된 것입니다

### 2-2. index.html에 URL 넣기

`index.html`에서 `const API_URL = "..."` 부분을 위에서 복사한 URL로 교체합니다.
(현재 값이 이미 들어 있으니, Apps Script를 재배포만 했다면 그대로 두셔도 됩니다.)

### 2-3. GitHub 업로드

저장소 최상단에 `index.html`을 그대로 올립니다. 하위 폴더에 넣으면 Vercel 기본 설정에서 열리지 않습니다.

### 2-4. Vercel 연결

1. Vercel → **Add New → Project → GitHub 저장소 선택**
2. Framework Preset: **Other**
3. Build Command / Output Directory: **비워둠**
4. **Deploy**

정적 파일이라 빌드 설정이 필요 없습니다.

## 3. 코드를 고친 뒤 반드시 할 일

| 고친 것 | 해야 할 일 |
|---|---|
| `index.html` | GitHub에 push → Vercel 자동 재배포 |
| `Code.gs` | Apps Script에서 **배포 → 배포 관리 → 수정 → 새 버전 → 배포** |

Apps Script는 저장만으로는 반영되지 않습니다. 재배포해야 실제 웹앱에 적용됩니다. 배포 URL 자체는 그대로 유지되므로 `index.html`은 다시 손대실 필요가 없습니다.

## 4. 구글시트 준비

### 필수 — `니즈접수` 탭 C열(요청부서) 드롭다운 해제

요청부서를 폼에서 직접 입력할 수 있게 되어, C열에 드롭다운(데이터 확인)이 걸려 있으면 저장이 거부될 수 있습니다.

C열 전체 선택 → **데이터 → 데이터 확인** → 규칙이 있으면 **규칙 삭제**

(규칙이 없으면 넘어가시면 됩니다. Apps Script가 저장 시점에도 한 번 더 해제하니 이중 안전장치입니다.)

### 선택 — `부서 관리` 탭 추가

부서 버튼 목록을 시트에서 관리하고 싶을 때만 하시면 됩니다.

1. 새 탭 생성 → 이름을 정확히 **`부서 관리`**
2. A1에 `부서명`, A2부터 한 줄에 하나씩 입력

이 탭이 있으면 폼 버튼이 자동으로 그 목록으로 바뀝니다. **없으면 기본 2개(채널마케팅본부·프로덕트마케팅본부)가 나옵니다.** 어느 경우든 `+ 직접 입력`은 항상 사용 가능합니다.

## 5. 점검 방법

Apps Script 편집기에서 **실행 → `checkSetup`** 을 누르면 하단 실행 로그에 다음이 표시됩니다.

- 니즈접수 탭 연결 상태
- 현재 접수 건수
- 기수 관리 / 부서 관리 탭 존재 여부
- 현재 적용 중인 부서 목록

화면에서 "구글시트에서 목록을 불러오지 못했습니다"가 뜨면 여기부터 확인하시면 됩니다.

## 6. 화면 기능

### 검색

검색창 왼쪽 드롭다운으로 **찾을 범위**를 고를 수 있습니다.

| 검색 대상 | 찾는 항목 |
|---|---|
| 전체 항목 (기본) | 접수번호 · 작성자 · 요청부서 · 제품명 · 상세 · 세미나종류 · 목표고객 · 기수 · 요청사유 · 기대효과 · 상태 |
| 접수번호 | 접수번호만 |
| 작성자 | 담당자 이름 |
| 요청부서 | 부서명 |
| 제품·서비스 | 제품명 · 상세 내용 · 제품구분 |
| 세미나종류 | 혼강 / 공부방 / 특집 / 신간런칭 |
| 목표고객 | 유치 · 초등 · 중등 · 고등 · 학원장 등 |
| 요청사유·기대효과 | 본문 전문 |

- **상태 필터**(접수완료 / 검토중 / 수락(채택) / 차기 검토 / 완료)와 **기수 필터**를 검색과 함께 걸 수 있습니다.
- 일치하는 글자는 노란색으로 표시됩니다.
- 조건이 걸려 있으면 **검색·필터 초기화** 버튼이 나타납니다.

> **참고 — 작성자 검색과 익명성**
> 목록·상세 화면에는 작성자와 요청부서를 표시하지 않지만, **작성자 이름으로 검색은 가능합니다.**
> 이름을 넣어 검색하면 해당 인물이 제출한 건이 조회되므로, 완전한 익명은 아닙니다.
> 본인 건을 쉽게 찾기 위한 기능이며, 익명성을 더 강하게 유지하려면 `SEARCH_FIELDS`에서
> `owner` · `dept` 항목을 지우고 `all`의 `pick`에서도 두 값을 빼면 됩니다.

### 새로고침

우측 **새로고침** 버튼을 누르면 구글시트를 다시 읽어옵니다.

- 검색어·필터·정렬 조건은 그대로 유지됩니다
- 불러오는 동안 버튼이 회전 표시로 바뀝니다
- 결과 줄 우측에 **마지막 갱신 시각**이 표시됩니다

---

## 7. 동작 방식 요약

- 구글시트 연동 성공 → 상단에 **구글시트 연동 — 실시간 반영** 표시
- 연동 실패 → **오류 배너 + 다시 불러오기 버튼** 표시 (예시 데이터가 실데이터처럼 보이지 않도록 목록을 비웁니다)
- `API_URL`을 비우면 로컬 데모 모드로 동작 (예시 데이터 표시, 브라우저에만 저장)
- 작성 중인 요청서는 브라우저에 자동 임시저장되며, 제출 성공 시 자동 삭제됩니다
